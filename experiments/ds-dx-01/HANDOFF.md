# DS-DX-01 · Architecture Session A

## Индивидуальный запуск WSL

Используйте WSL2 и каталог Linux с правами 0700. Понадобятся Python 3.10+, Git, Poppler и libseccomp2. Установленные pypdf и pdfplumber используются для дополнительных сверок. Исходный PDF можно положить в приватный каталог до запуска или взять из DS-DC-05A. При загрузке используйте точный публичный URL из протокола. Preflight блокирует сокеты через seccomp и проверяет байты, страницы, табличные якоря, Git blobs и mock-тесты.

Из чистого checkout зафиксированного экспериментального коммита выполните бесплатную проверку. Замените два пути своими.

```bash
./experiments/ds-dx-01/preflight.sh --pdf '/private/ORIGINAL.pdf' --state '/private/ds-dx-01-state'
```

После успешной независимой WSL Validation Session и отдельного финансового GO запустите следующую команду с одобренной суммой. Число `1.00` в примере отражает предложенный протоколом предел. Терминал ожидает фразу `GO USD 1.00` и один скрытый ввод ключа. По умолчанию запрашиваются 12 пар. Флаг `--negative` разрешает ещё до четырёх пар в рамках той же суммы.

```bash
./experiments/ds-dx-01/live.sh --pdf '/private/ORIGINAL.pdf' --state '/private/ds-dx-01-state' --owner-go-usd 1.00
```

Перед GO повторно сверьте цены, спецификацию контекста, Files API и Chat Completions по официальным ссылкам ниже. Если изменились условия, используемые в бюджете, необходим новый проверенный пин кода. Суммы хранятся в целых нанодолларах. Проверенный тариф U — $0.014625 за 65 страниц. Верхний резерв D — $0.3538944. Верхний резерв пары A/B — $0.6340608. Общая стартовая проверка U + D требует $0.3685194. При бюджете $1 число пар зависит от измеренного расхода и остатка. При остановке сохраняются полные и неполные пары. Шаги выполняются последовательно; повторный LIVE в том же каталоге блокируется. При неизвестной операции сначала сверить приватный журнал с биллингом и Files API. Удаление файла требует отдельной политики владельца.

Успешный сбор или ожидаемая остановка создаёт `live/DS-DX-01.zip`. Аварийное завершение процесса или отказ диска могут оставить только приватные файлы. Проверка ZIP после передачи:

```bash
unzip -t DS-DX-01.zip
mkdir verified && unzip -q DS-DX-01.zip -d verified
(cd verified && sha256sum -c SHA256SUMS)
```

## Приёмка

Передать ZIP Architecture Session A после просмотра экспортируемой копии. Исходник, сырые тела, идентификатор файла и ledger хранятся в приватном WSL. Tарифная оценка на основе `usage` использует пиковые ставки. Сверить фактические списания в кабинете владельца. A/B сравниваются по фактическим `usage.prompt_tokens`; отдельно записываются байты и токены D. Для standalone Markdown официальный архив локального токенизатора не удалось загрузить в облаке (HTTP 403). Поле `content_tokens` остаётся пустым. Токены генерации D и контекст B имеют разные значения и цели.

Эталон хранится отдельно. Оценщик проставляет для каждого A и B `supported / partial / unsupported / contradicted / fabricated`, физические страницы и критичность. Для ESSENCE по каждому assertion_id проставляется `preserved / partial / omission / contradiction` с цитатой и физической страницей. Сопоставить ошибки A и B, выделить потери от сжатия, поздние страницы, выводы из схем и ошибки, общие для двух плеч. Сверить три порога протокола и снижение стоимости. В отчётах `PASS` означает завершённый сбор, инженерная и научная приёмка отражаются отдельно. При неполных парах или отсутствии первичных подтверждений научный вывод остаётся INCONCLUSIVE.

## Допуск и результаты

- CLI принимает отдельный `controlled_calibration` GO на один закреплённый вопрос. Сервер проверяет SHA чистого HEAD, манифест, отчётный wire fingerprint, точные лимиты, reviewed contract, срок, run, аккаунт, проект, отпечаток ключа и путь общего приватного ledger. Контекст обоих запросов включает полные утверждённые досье и пустую историю. В режиме обычных вопросов требуется доказанная граница. `REVIEWED_BOUNDS` не пополнялся.
- Последовательность фиксируется в существующем durable Ledger. Ключ операции привязан к wire в общей кампании и блокирует повтор с другим request ID после перезапуска. Q02 требует отдельный GO с SHA подтверждённого GO Q01 и запись Q01 со `state=settled`, `finish_reason=stop` для той же учётной области и HEAD. Если уже есть binding для одобренного PDF, CAL останавливается до сети. Штатный холодный протокол предписывает загрузку закреплённых 4 или 10 оригиналов.
- Ledger атомарно сохраняет денежный результат, резервы и удержания, SHA источников и связи, estimate, usage с hit/miss и reasoning tokens при наличии, длительность upload/chat, finish reason, исходный черновик и claims/locators, диагностику. Черновик предназначен для локальной сверки и не меняет техническую память. Из поля черновика удаляются совпавшие ключ и file handles. Отдельное поле `reasoning_content` провайдера не сохраняется. Финансовая запись и калибровочные данные переживают выход из CLI, приватная телеметрия подпадает под прежнюю 30-дневную очистку, а блокировка повтора сохраняется.
- Для известного usage с finish, отличным от `stop`, ledger сохраняет receipt и удерживает резерв. Ошибка HTTP, неполный usage и превышение резерва останавливают серию. Для сверки начисления, тарифов и успешности Q01 предусмотрен отдельный шаг владельца, поскольку API response не удостоверяет фактический биллинг и неизменность версии за алиасом.

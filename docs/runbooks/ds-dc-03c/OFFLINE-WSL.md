# DS-DC-03C-R2 · Независимая офлайн-приёмка WSL

Скачайте `scripts/validation/validate_dc03c.py` по ссылке на конкретный коммит из сообщения о поставке. Сохраните его в WSL как `~/validate_dc03c.py`. Запустите один раз, передав согласованный reviewer точный SHA:

```bash
python3 -I "$HOME/validate_dc03c.py" --prepare --commit "${DS_DC_ACCEPT_SHA:?укажите согласованный итоговый SHA}" --site "${SATURN_SOURCE:?укажите абсолютный путь к checkout Saturn}"
```

Закреплённый checkout Saturn расположен вне корня DC-03B. Передайте его фактический путь через `--site` или используйте ранее заданный `SATURN_SOURCE`.

Лаунчер использует Git и системный Python 3.10 или новее для подготовки. Он ищет входы в `~/ds-dc03b-validation/` и повторно использует найденное окружение Python 3.12 с закреплёнными зависимостями, кэш DC-03B, checkout Saturn и подлинный Q01. Поиск проверяет пин сайта, SHA fixture и токенизатора и размер и SHA всех 14 PDF. Полный preflight проверяет freeze, физические страницы и версии зависимостей. Для него нужны `prlimit`, `pdftotext` и `pdfinfo`. [Прежние локальные входы](../ds-dc-03b/OFFLINE-WSL.md)

Если у владельца уже заданы `SATURN_SOURCE`, `DS_DC_CACHE` и `DS_DC_Q01_CANDIDATE`, лаунчер использует эти пути. `--wsl-root` задаёт другой корень поиска. При нескольких кандидатах либо нестандартном размещении передайте точный путь через `--site`, `--cache`, `--fixture` или `--python /path/to/venv/bin/python`. При отсутствии или неоднозначности входов создаётся ZIP с причиной. Существующие checkout и материалы используются для чтения. Архивы и отсутствующие входы лаунчер не скачивает и не распаковывает.

На этапе подготовки Git fetch получает только ветку Draft PR #4. Лаунчер проверяет, что пин входит в её историю после исходного HEAD R2, и создаёт отдельный чистый checkout. Затем запускается офлайн-runner. Опциональные повторяемые аргументы `--extra-tests /path/to/test_independent.py` и `--protected-file /path/to/file` добавляют заранее просмотренные тесты reviewer и сверку явно указанного файла. `--network namespace` требует Linux network namespace и доступных `unshare` и `ip`. Режим `auto` указывает в отчёте, применён ли namespace или Python socket guard. Python guard покрывает Python socket API, включая Python-подпроцессы. Системные вызовы сторонних бинарников требуют namespace.

Один ZIP сохраняется в `C:\DS-Validation\Reports` (WSL `/mnt/c/DS-Validation/Reports`). Приватный WSL-каталог с сырым JUnit и логами указывается в терминале. Архив содержит Markdown, `summary.json` и `checks.json` с безопасными строками по тестам, R01, mock-сценариями, метриками полезности, историческим sizing, wire и scope wire и геометрическими локаторами пяти подлинных claims Q01, если replay состоялся. Диагностика также содержит категории контекста, коды причин, блокирующие признаки строки и координаты фрагментов без текста источника. Сырые сообщения об ошибках, параметры приватных тестов и источники отсутствуют в пересылаемом файле. Свойства allowlist, screening, CRC и SHA-256 проверяются до выдачи архива. Обычный FAIL возвращает код 1 и сохраняет доступные результаты.

Reviewer сверяет отдельный WSL baseline DC-03B `53287 / 315382`, 5/5 supported по подлинному Q01, исторические матрицы, R01, происхождение новых выдержек и отсутствие внешних операций. Полный прогон требует минимум 282 тестовых случая и ноль skips. Размер PDF-текста зависит от среды Poppler. Архивные оценки других сред сохраняются в прежних отчётах.

## Тракт и приёмка

`python -m ds_dc` строит реестр из закреплённого checkout. При локальном вопросе сервер сохраняет исходную строку и hash, выбирает записи каталога, проверяет готовность, хеши и mock-привязки, резервирует cold/miss расчёт, разрешает один mock chat и проверяет CandidateAnswer. Для БКД в `mock-wire-redacted.json` четыре file-part, полный Markdown (в отчёте его размер и хеш), thinking enabled, 4096 completion, без tools. Форма file-part подтверждена архивным скриптом DS-LV-02-P6. Контракт полного запроса и разрешённые параметры для будущего live следует подтвердить отдельно по DS-LAB-06 и актуальной документации.

Независимое ревью привело к исправлениям допуска сессии, mapped IPv4, точного сравнения числовых суффиксов, сравнения с активной темой, обработки кэша preflight и отказа при сбое аудита. Тесты используют реальные закреплённые PDF для состава, контролируемого drift и проверки цитаты. Транспорт проверен в сценариях с отключённым Python socket и инертной переменной API key.

`resolver.json` содержит случаи, варианты выбора с оценками и источниками, готовность, нерешённые части и mock-счётчики. Первоначальный сценарий 11 предполагал, что АРМ СЛДКС относится к ПО. Пин сайта классифицирует эту карточку как аппаратное рабочее место. Для сценария ПО взята утверждённая группа АРМ LANMON. Проверка на кириллическом «БУСЛоРа» сохранена как holdout: в карточке есть BUSLORA и BusLoRa, разрешённого кириллического алиаса не найдено. Результат безопасно завершился уточнением.

- **IMPORTANT** · Mock-допуск, счётчики и техническая память действуют в одном процессе CLI. Markdown-журнал с атомарной записью и очисткой при записи сохраняется локально. HTTP ingress и доверенный proxy, устойчивость admission/billing при рестарте и между процессами, независимый publication gate и подтверждение лимита expansion относятся к последующей интеграции. 64 000 — параметр mock-оценки; 4096 включает reasoning. ## Воспроизведение и передача

Переменные `SATURN_SOURCE` и `DS_DC_CACHE` указывают на закреплённый read-only checkout и каталог кэша. Для исторического набора тестов `SATURN_BKD_PDF` и `SATURN_SLD_PDF` указывают на локальные оригиналы с хешами из реестра. Зависимости из `requirements-dev.txt`, системные Git, curl и утилиты Poppler.

```sh
python -m ds_dc --site "$SATURN_SOURCE" --cache "$DS_DC_CACHE" --fetch --evaluate output
python -m ds_dc --site "$SATURN_SOURCE" --cache "$DS_DC_CACHE" \
  --question 'Сколько весит БКД-ПК-RF.2?' --question 'А как его хранить?'
python -m unittest discover -s tests -p test_dc01.py
python -m pytest -q
git apply --check DS-DC-01-CLOUD.patch
sha256sum -c SHA256SUMS.txt
```

При повторе оценки на уже скачанных байтах убрать `--fetch`. Итоговый запуск pytest — `116 passed, 2 warnings in 63.60s (0:01:03)`. Отдельный запуск DC-01 — 17 тестов, OK. Результаты команды тестирования приложены в `dc01-tests.txt` и `tests.txt`. Патч опирается на указанный HEAD, список файлов и суммы поставки приложены. Для переноса после отдельного решения владельца предлагается проверить и применить патч на точную базу и согласовать commit/PR в выделенной ветке.

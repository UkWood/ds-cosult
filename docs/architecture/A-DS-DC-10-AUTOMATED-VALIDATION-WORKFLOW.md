# A-DS-DC-10 · Automated Validation Workflow

**Решение утверждено владельцем для DS-DC-03C.** Независимый reviewer задаёт точный SHA принимаемого checkout. Владелец запускает одну команду из отдельного чистого checkout с уже подготовленной WSL-средой, локальным кэшем и подлинным Q01. Канонический freeze, оригиналы, исходный пин сайта и fixture проверяются до зависимых проверок.

Сценарий запускает независимые этапы по отдельности. Для каждого этапа фиксируются среда, пин, длительность, статус и код завершения. Блокировка обязательного входа исключает общий PASS. Дополнительно предоставленные проверяющим тесты запускаются отдельно. Полный регрессионный прогон требует ноль skips.

Предпочтительная изоляция включает отдельный Linux network namespace с loopback и Python socket audit guard. При недоступности namespace режим `auto` явно фиксирует Python-only fallback. Этот режим ограничен Python socket API. WSL может потребовать `--network namespace` для обязательной системной изоляции. Проверки используют временные журналы и локальные fixture.

Один ZIP содержит сформированные сводки, результаты по этапам, сведения о screening и SHA-256 членов архива. Raw output и JUnit остаются в приватном локальном каталоге. ZIP проходит проверку списка членов, чувствительных паттернов, CRC и хешей перед переносом. Владелец просматривает и передаёт ZIP вручную. PASS автоматизации и решение независимого reviewer фиксируются отдельно.

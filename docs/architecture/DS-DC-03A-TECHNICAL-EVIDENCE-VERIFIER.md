# DS-DC-03A · Technical Evidence Verifier

1. Проверять схему, привязку к запросу и каждый claim отдельно. Сохранять причины отказа и все нерешённые части. Ошибка общей схемы блокирует результат.
2. Восстановить идентичность из Source Registry. Проверить SHA исходных байтов, редакцию и физическую страницу либо точное поле Markdown. Проверять связь источник → изделие → поколение → компонент по утверждённой применимости. Похожее название такой связи не устанавливает.
3. Установить дословные опоры в координатах источника. Для таблицы хранить заголовок, строку, колонку, границы ячейки и сведения об объединении ячеек. Неопределённый перенос или layout требует ручной проверки страницы. Для диагностики отдельно показать NFC, пробелы, регистр, кавычки и извлечения plain/layout. Числа, символы и единицы не заменять ради совпадения.
4. Проверить техническую связь. Для количества установить оператор, число, единицу, условие и область. Для troubleshooting доказать связь симптом → возможная причина → применимое действие. Точные цитаты из разных строк не подтверждают их связь. Последовательность требует явной отдельной опоры.
5. Проверить полноту по частям вопроса. Для свободного текста V1 вручную проверить тезисы вне claims. В V2 renderer выводит только поддержанные claim ID и нерешённые части.

Результат каждого claim должен содержать восстановленную идентичность, опоры, причины отказа, покрытые части и раздельные механический и технический вердикты. Положительная техническая оценка и противоречие требуют независимого решения либо доказуемого правила для известного типа. В стенде supported_fixture выдаётся только для заранее заданного синтетического эталона. При отсутствии подходящего эталона сохраняется semantic_pending даже при точных цитатах.

## Предлагаемый объём DC-03B

- Принять исходный Q01 с pin и зафиксировать ожидаемые вердикты для каждого claim и locator. Утвердить схему V2 и детерминированную привязку коротких ID.
- Прототипировать локальную разметку строк и колонок GT01 с физическими координатами и объединёнными ячейками. Сверить изображение таблицы вручную. Расширять только типы с независимо проверенными эталонами.
- Добавить shadow-сравнение сохранённых результатов, строгую проверку покрытия и renderer из claim ID. Изменение production gate потребует отдельного решения.

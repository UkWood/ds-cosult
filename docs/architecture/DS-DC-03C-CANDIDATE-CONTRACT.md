# DS-DC-03C · candidate-answer/2.1

Нормативный офлайн-вход находится в `ds_dc.evidence_integration`. Он переиспользует Resolver, состав полного разрешённого досье, порядок чтения и ограничения прежнего Pilot. В запрос входят исходный вопрос, его части, релевантные вопросы той же темы, короткие серверные ID, страницы сайта и все PDF разрешённого досье в виде Native PDF slots. Исторические `candidate-answer/2`, `2-lab` и CAL сохраняют свои форматы.

## Запрос и отпечатки

Пакет имеет форму Chat Completions с моделью `deepseek-flash`, `thinking.type=enabled`, `reasoning_effort=high`, JSON response format, без stream и web tools. Максимум генерации 8192 токенов. Значения `OFFLINE_SLOT_n` обозначают порядок исходных PDF; одинаковые байты занимают один slot. Полный операторский payload CLI содержит исходные данные и эти метки.

Registry fingerprint привязывает источник к запросу, манифесту, частям вопроса, записи изделия, поколению, SHA, редакции, canonical URL и Git commit/blob. Wire SHA-256 считается по каноническому UTF-8 JSON массива `[prompt_version, registry_fingerprint, ordered_pdf_sha_and_slot, payload_without_wire_identity]`. Затем wire identity помещается в метаданные модели. При изменении точного вопроса, истории, промпта, состава, порядка, модели или реестра меняется wire. Короткие ID связаны с fingerprint, а ответы дополнительно связаны с точным wire. Встроенный CLI ожидает уникальный request ID, повтор которого предназначен только для воспроизведения того же офлайн-пакета.

## Ответ модели

Пакет ограничен 512 КиБ UTF-8. Дублирующиеся JSON-ключи, значения NaN/Infinity, одиночные суррогаты, неизвестные верхнеуровневые поля, несовпадающая версия или идентичность, повтор ID и неверные ссылки верхнего уровня блокируют пакет. Верхний уровень содержит ровно:

```json
{
  "version": "candidate-answer/2.1",
  "request_id": "<from request>",
  "wire_identity": "<from request>",
  "claims": [],
  "answer_claim_ids": [],
  "evidence_extracts": [],
  "unresolved": ["P1"]
}
```

- Все списки верхнего уровня ограничены 32 элементами. ID claims и extracts уникальны во всём пакете, в формате `[A-Za-z][A-Za-z0-9_-]{0,47}`. `answer_claim_ids` выбирает подмножество claims. `unresolved` содержит ID известных частей.
- Claim содержит `id, entity, kind, subject, value, unit, comparator, qualifier, condition, parts, evidence`. Формы, операторы, единицы, модальность и роли соответствуют техническим правилам [V2](DS-DC-03B-CANDIDATE-CONTRACT-V2.md). Evidence содержит `role, source, page, quote` и допускает необязательный `hint` из контракта V2. Координаты сервер проверяет и определяет по оригиналу.
- Extract содержит `id, entity, source, quote, conditions, parts` и ровно одно поле `page` (физическая страница PDF с единицы) или `field` (сайт). `conditions` содержит до восьми дословных условий. Допустимы текстовые YAML-поля `title, name, summary, description, applications, features, notice, interfaces, protocols, connectors, specs`; для списка указывается индекс. Для `specs[i]` с полями `name` и `value` цитата имеет вид `name: value`, сохраняя оба исходных значения. `line:N` или `line:N-M` означает целый абзац Markdown. Другие формы остаются открытыми.

Для цитат применяется NFC и сведение последовательностей пробельных символов к одному пробелу с удалением краевых пробелов. Регистр, цифры, единицы, отрицания и знаки сохраняются. Техническое сопоставление целых фраз дополнительно нормализует регистр по историческому правилу. Кавычки, знаки сравнения и числовая грамматика сверяются с первоисточником. Верифицированные числовые пределы выводятся в исходном виде.

## Сборка и границы

Результат содержит `answer, status, confirmed_elements, extracts, citations, unresolved` и отдельные операторские `diagnostics`. Публичные поля ссылок содержат provenance и координаты. Полные соседние ячейки и отклонённый материал присутствуют в операторских diagnostics. Рендерер берёт текст и значения из источника. Он сохраняет модальность возможной причины и ограничивает выдачу потенциально опасных указаний.

Доказанную полноту можно отметить отдельной серверной сверкой, связанной с wire, частью вопроса, выводимым материалом и provenance. Текущий CLI работает без такого допуска. Для вопросов с явными границами сервер сохраняет отдельные части, а неразделимый составной вопрос сохраняет целиком. Модельные `unresolved` и `parts` учитываются как сигналы, сохраняя пробелы при отсутствии независимого покрытия. `partial` содержит проверенные технические сведения. `reference` содержит атрибутированные выдержки или ссылки. `needs_support` сохраняет запрос для сверки.

PDF-адаптер ограничен 12 целевыми страницами за ход с отдельными локальными проверками применимости по обложкам. Поддерживаются строки простых таблиц с покрытыми вертикальными объединениями и прозовые блоки с наблюдаемыми границами. Неясные многоуровневые заголовки, OCR-only, продолжения, поперечные связи и свободный смысловой пересказ требуют отдельной проверки. Сверка противоречий ограничена технически установленными числовыми позициями пакета для совпадающей области. Для досье сверх cap доступна справочная ссылка на карточку. Режим закрыт для пользовательского, финансового и сетевого входов.

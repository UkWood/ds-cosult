## 2. Целевая схема

Admission → Topic & Entity Resolver → Active Dossier Manager → File Registry + Context Builder + Financial Guard → один D1 (DeepSeek Flash, Native PDF + Deep Thinking) → CandidateAnswer → независимая проверка → ответ.

Принцип: искать для модели документацию, а не готовый ответ вместо неё. Hybrid Evidence Context не развивать. Не вводить обязательный retrieval по отдельным техническим фактам, вторую LLM для отбора/проверки, локальную LLM или AI Tunnel. P0 — локальная навигация/заранее подтверждённые ответы.

Различать доступность файла, покрытие корпуса, состав выбранного досье, достаточность ответа. Полная доступная область не означает полный ожидаемый корпус. Сведения из других модификаций не приписывать целевой; наличие ссылки доказывает связь, не каждое утверждение о применимости. ## 4. Topic & Entity Resolver и память

Локальный поиск по каталогу: точные названия, нормализованные обозначения, доказанные алиасы, нечёткий поиск без изменения значимого суффикса, лексические признаки назначения. Явное точное изделие приоритетнее прежнего контекста и page hint. Не угадывать неизвестный вариант. Общий интерфейс не выбирает автоматически другое изделие. Без явной новой темы сохранять активное досье при продолжениях («Какие интерфейсы?», «Резервное питание?», «Условия хранения?»), а при конфликте/неясном референте уточнять. Функциональный вопрос без имени — поиск релевантных тематик, при неоднозначности короткое содержательное уточнение. Сравнение и системы — union подтверждённых досье, дедупликация по SHA с сохранением всех связей. Не раскрывать предыдущие ответы другого изделия как доказательство. Сохранять исходный вопрос полностью, историю реальных ролей или явных непривилегированных данных, все необходимые условия, выбранные ID/версии. Ограничивать историю по контексту, не фиксированным четырём сообщениям; диагностика свёртывания, не терять важную неразрешённую часть. Не включать reasoning_content, секреты, IP или чужую историю в prompt.

## 5. A-DS-DC-03 — утверждённая политика

| Параметр | Значение |
|---|---|
| Вход штатный / расширенный | 128 000 / 256 000 токенов всего запроса |
| Генерация, включая reasoning | max_tokens = 8192 |
| Модель | прямой API deepseek-flash |
| Thinking | enabled, reasoning_effort high |
| Видимый ответ | цель 200–450 токенов, подробный до 1200 |
| Chat POST | не более одного на принятый вопрос; автоматических повторов 0 |
| Native web/tools | отключены |
| Публичный бюджет (не разрешение запуска) | $30/месяц, $2/день глобально, $0,50/IP/день |
| Предупреждение | $24/месяц |
| Штатный / расширенный резерв | $0,05 / $0,09 при доказанной границе входа и утверждённом тарифе |
| Пилот DC-02 | основной $2,50, резерв $0,50 только отдельным GO; до 24 штатных и 8 расширенных chat POST, до 1000 обработанных страниц |

Плановые расчётные пиковые ставки из согласованного A-DS-DC-03 и DS-LAB-06: $0,30/млн input miss, $0,006/млн hit, $1,20/млн completion, $0,225/1000 обработанных страниц. Проверить актуальные официальные тарифы, условия Files API, семантику max_tokens, fit модели до GO; при непроверенном изменении остановить, не считать эти цены неизменными. При таких ставках 24×$0,05 + 8×$0,09 + $0,225 = $2,145 по обычным резервам, без специальных калибровочных резервов. Все лимиты применяются одновременно; лабораторный профиль и публичный профиль раздельны, публичный закрыт. Принятый бюджет не означает разрешение на расход.

128/256k — лимиты **полного входа**: system, весь prompt, история, метаданные, фактически разобранный контент PDF. Расширенный режим выбирается сервером; клиент не задаёт cap. Учитывать отдельно выходной резерв и контекстное окно/лимиты Files API. Исторический estimate = UTF-8 bytes JSON + 500×pages — не токены; удалить из решения о live admission. Локальный токенизатор и извлечение могут дать оценку с запасом, не математическую верхнюю границу native expansion. Раздельно фиксировать estimate, verified upper bound (если есть), observed usage. Не обещать жёсткий preflight при неизвестной экспансии. Без доказанной верхней границы для обычного live dispatch — отказ. Для изучения expansion предусмотреть отдельный операторский calibration mode только по явному GO с проверенным документированным максимальным тарифицируемым объёмом, cold reserve на него, отдельным журналом и пределом операций; он может превысить целевой cap и не считается обычным успешным запросом. Если нет доказанного максимума стоимости, не отправлять. Расширение калибровочного режима не является разрешением на выход за $2,50/32 POST/1000 страниц. При обнаруженном превышении границы остановить серию и сверить бюджет. Не срезать PDF и обязательные части вопроса скрыто; предложить явное тематическое сужение, сохранить пробелы.

Отдельное решение A-DS-DC-04 допускает контролируемую калибровку только на двух закреплённых запросах, по отдельному GO на каждый и с принятием остаточного финансового риска. Для ordinary действует строгий допуск выше. [A-DS-DC-04](A-DS-DC-04-CONTROLLED-CALIBRATION.md)

## 6. Native PDF Lifecycle / устойчивый финансовый guard

Публичные оригиналы загружать по востребованности, вне D1 до chat, дедупликация/lock по account/project + sha + purpose/parser; исходный file_id только из собственного реестра. `text_recognition` — путь D; availability/status, expiry, ready и привязку проверить до chat. Не принимать вымышленный TTL или ready. Не гарантировать совместимость file_id между сессиями до испытания. Отдельные операции upload/status/delete, все учитываются и ограничены manifest/GO, без автоматического повтора неопределённой операции. Удаление только своих файлов после подтверждения владения, учитывать активные потребители, 404 до DELETE не доказательство удаления. Ни одного visitor upload. Не передавать в модель произвольные URL; модель не имеет инструментов. Реальный транспорт включается только после авторизации владельца, по точному run ID/manifest/лимитам. Secret вводится в доверенной среде владельца, не в промпте, UI, Git, логах.

Pre-reserve атомарно до отправки с учётом miss цены, максимальной генерации, отдельных файлов, глобального/day/IP/run лимитов, нескольких процессов/перезапуска. После полного usage settled actual,освободить остаток; при неизвестном начислении удерживать резерв и блокировать серию, ручное урегулирование только владельцем. Не применять CR01 старого run как универсальный retry. Долговечный журнал операций без БД, lock и атомарная запись с recovery, идемпотентность запросов и операций. Отдельно считать оплачиваемые попытки, вопросы, usage и holds. При отсутствии средств P0 доступен в пределах квот.

## 7. Допуск, интерфейс, проверка

Наследуются 1 анонимная активная сессия/IP, 15 минут неактивности — удалить техпамять, 30 минут — reset серии, 20 вопросов/IP/сутки включая P0, первые 5 сразу, с 6-го возрастающая задержка, после 10 последовательных — поддержка; вопрос ≤1200 Unicode, HTTP JSON ≤8 KiB. F5 сохраняет сеанс, canonical IP только из доверенного ingress. Закрытый audit Markdown вопрос/ответ/IP/UTC, 30 дней; без БД, секретов, чужого доступа и передачи IP провайдеру. Инструкции посетителя и документный текст не меняют системный policy. Сохранять «Не выдумывай недостающие технические характеристики». 

DC-02 — закрытый интерфейс владельца (локально/или иной отдельно одобренный доступ); draft-only. У вопроса серверные hash/dossier IDs; candidate answer, claims, scope/component, значение/единица/квалификатор/условие, locators (doc_id или source page identity, редакция/hash, физ.страница/раздел/таблица или field path, дословная опора), unresolved. Доказательство может быть исходной страницей сайта или PDF. Связка file_id↔doc_id должна быть однозначной, включая дедупликацию. Не выдавать проверку подстроки за смысловую верификацию. Формат неизвестной страницы/непроверенной цитаты — явная неопределённость. Черновик виден оператору с меткой; отдельный verified result только по независимому подтверждению. Не разрешать renderer добавлять факты. Для произвольных новых утверждений полноценная проверка остаётся DC-03; высокий риск (подключение, электропитание, метрология) обязательно сверять с оригиналом и поколением. Не обещать публичное качество по успеху mock или одному диалогу.

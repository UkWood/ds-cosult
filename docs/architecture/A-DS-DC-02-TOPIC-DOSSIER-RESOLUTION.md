# A-DS-DC-02 — Topic & Entity Resolution / Dossier-Level Retrieval

**Дата:** 20 ноября 2026. **Проект:** DS-консультант (`UkWood/ds-cosult`). **Статус:** архитектурный принцип согласован владельцем; проектные детали ниже — реализация в DC-01, без разрешения на платные операции или внедрение.

## Основание
В ручном DeepSeek Chat владелец сначала указал изделие БКД-ПК-RF.2, его страницу и все связанные PDF, тем самым ограничив предметную область. В DS-LAB-06 документный контекст также был выбран заранее. Успех режима D подтверждает перспективность целостного досье, но не доказывает качество автоматического выбора темы. При полном корпусе сайта этот выбор должен выполнять консультант.

## Нормативное решение
**Не искать ответ для модели. Искать для неё документацию, в которой содержится ответ.**

1. До D1 выполнять локальный Topic & Entity Resolver над вопросом, доверенной подсказкой страницы и контекстом сеанса. Искомые объекты: изделия/модификации, системы, ПО; поисковые признаки: обозначения, аббревиатуры, термины, компоненты, функциональное назначение и описание инженерной задачи.
2. Строить компактный тематический каталог из закреплённого исходного контента сайта до Astro, а не из сгенерированных HTML или всех PDF-фрагментов. Связь с документами выводить из фактических ссылок/структуры и подтверждённой применимости; не угадывать URL, принадлежность или технические свойства. Индексация для маршрутизации не является верификацией фактов.
3. Выбирать целое тематическое досье: исходный контент нужных страниц и все разрешённые PDF по их ссылкам. В системном досье использовать подтверждённые связи с relevant изделиями/ПО; не расширять рекурсивно до всего сайта. Не считать неполное досье полным; до dispatch проверять готовность, версии, применимость и вместимость.
4. Active Dossier Manager поддерживает продолжение темы, явную смену, ограниченное расширение, сравнение. При смене темы не наследовать неподтверждённые факты прежнего изделия как знания о новом. Явное название имеет приоритет над page hint и историей; неоднозначность конкретной модификации не разрешать догадкой. Общий термин RS-485 сам по себе не выбирает конкретный контроллер.
5. Первые методы: точные идентификаторы, безопасная нормализация регистра/дефисов/смешанного написания, подтверждённые алиасы, нечёткий и лексический поиск по каталогу. Семантический поиск по компактному каталогу — только после измерения недостатков базовых методов. Не вводить обязательный дополнительный LLM-вызов. При неоднозначности — короткое содержательное уточнение; при допустимом сравнении — объединение полных досье с дедупликацией файлов. Недоступное досье и over-cap — явный отказ/ограничение с сохранением нерешённых частей вопроса, не скрытый top-K PDF.
6. Native PDF + Deep Thinking анализирует выбранные материалы; web tools отключены. Verification после генерации остаётся обязательным принципом. Не возобновлять развитие Hybrid Evidence Context как основной путь знаний.

## Включение в план
DC-01: каталог на реальном закреплённом исходнике всего сайта (метаданные/ссылки, без массового скачивания и upload), два готовых пилотных досье BKD и SLDKS. Остальные записи честно помечать неготовыми, если документы не закреплены. Проверить 12 сценариев из обновлённого задания; фиксировать выбранные ID, признаки, причины, полноту и ошибочные выборы. DC-02: реальные вопросы без названий и смена/сравнение тем в пределах разрешённого набора. Масштабирование и семантический поиск — по результатам, не заранее.

Это решение дополняет A-DS-DC-01. Все прежние гарантии безопасности, полноты вопроса, бюджетные ограничения и запреты на платные вызовы/merge/deploy сохраняются. Автоматический выбор досье не проверен лабораторией D; утверждать его успешность до DC-01/02 нельзя.
